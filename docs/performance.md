# Replication performance

Measured end to end: the connector runs as a subprocess, exactly as the Airbyte
platform runs it, and RECORD messages are counted against wall-clock time. The
figures therefore include the SAP round trips, DuckDB, the CDK's serialization
and the write to stdout — not just the extraction.

Best of 2 run(s) per case. Generated by `bin/benchmark.py`.

| Case | Records | Time | Records/s | MB/s | Peak RSS |
|---|---:|---:|---:|---:|---:|
| RFC DD02L, serial | 164,673 | 19.3s | 8,519 | 8.9 | 1,931 MB |
| RFC DD02L, 2 partitions | 164,673 | 162.2s | 1,015 | 1.1 | 2,409 MB |
| RFC DD02L, 4 partitions | 164,673 | 242.2s | 680 | 0.7 | 2,409 MB |
| RFC DD02L, 8 partitions | 164,673 | 334.5s | 492 | 0.5 | 2,411 MB |
| RFC DD02L, 16 partitions | 164,673 | 347.6s | 474 | 0.5 | 2,411 MB |
| RFC DD02L, 2 of N columns | 164,673 | 6.6s | 25,128 | 3.1 | 2,411 MB |
| RFC SBOOK, 8 partitions | 28,782 | 15.7s | 1,833 | 0.9 | 2,411 MB |
| ODP full ZJRODPVSQL$F, 1 thread(s) | 3,001 | 1.9s | 1,575 | 0.4 | 2,411 MB |
| ODP full ZJRODPVSQL$F, 4 thread(s) | 3,001 | 1.8s | 1,662 | 0.5 | 2,411 MB |
| ODP full ZJRODPVSQL$F, 8 thread(s) | 3,001 | 1.9s | 1,579 | 0.4 | 2,411 MB |
| ODP over OData, initial load | 3,001 | 2.7s | 1,104 | 0.3 | 2,411 MB |

## Effect of partitioning

| Partitions | Records/s | Speed-up vs serial |
|---:|---:|---:|
| 0 (serial) | 8,519 | 1.00x |
| 2 | 1,015 | 0.12x |
| 4 | 680 | 0.08x |
| 8 | 492 | 0.06x |
| 16 | 474 | 0.06x |

## Notes

- **RFC DD02L, serial** — baseline: one RFC_READ_TABLE call chain
- **RFC DD02L, 2 of N columns** — projection pushed to SAP
- **RFC SBOOK, 8 partitions** — wider rows

## Environment

- Host: Linux-6.18.46-1-lts-x86_64-with-glibc2.44, 32 CPUs
- Python 3.13.12
- SAP: localhost client 001

The SAP system here is a single-container ABAP trial sharing a laptop with the
connector, so these are *relative* figures for comparing settings, not a
capacity statement about production hardware.
